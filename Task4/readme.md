** Доработка архитектуры MVP решения по открытию депозитов: передаче ставок в кол-центры

### <a name="_3bfxc9a45514"></a>**Функциональные требования**

Команда обнаружила проблему: большинство клиентов банка «Стандарт» — пожилые люди. Как только банк запустит
маркетинговую кампанию на текущих и на новых клиентов, количество звонков в кол-центр может увеличиться. Есть риск, что
возрастным людям будет непросто сориентироваться в новых процессах и они захотят уточнить условия открытия депозита по
телефону.

В ходе анализа проблемы сотрудники банка внесли несколько предложений:

1. Нужно, чтобы сотрудники кол-центра могли проконсультировать клиентов хотя бы по текущим ставкам банка. Для этого надо
   каким-то образом предоставить их системе доступ к ставкам по депозитам.
2. Есть риск, что кол-центр будет перегружен. Поэтому необходимо подключить к работе партнёрский кол-центр. При этом
   важно, чтобы сотрудники партнёрского кол-центра также могли проконсультировать клиентов по актуальным депозитным
   ставкам. Для этого нужно наладить процесс передачи информации об актуальных ставках между банком и кол-центром.
   Кол-центр партнёра работает во внешней информационной системе относительно банка. Они готовы получать актуальные
   ставки в виде файлов. Нет возможности сделать API-вызовы (например, через SFTP-протокол).
3. Все эти изменения необходимо учесть в MVP и предложить решение на основе текущего процесса работы со ставками.

### <a name="_qmphm5d6rvi3"></a>**Решение**

В АБС предлагается произвести доработку интерфейса для возможности загрузки файла со ставками по депозитам.
Бэкенд АБС дорабатывается в части функции передачи файла со ставками по депозитам в сервис управления депозитами
с использованием брокера сообщений.
Сервис обрабатывает файл из kafka дважды и по протоколу SFTP передаёт файл в колл-центр банка и в партнерский кол-центр.
В условиях наличия интеграции с СМС - в случае ошибки/успеха можно направлять СМС ответственному со стороны банка
о результатах успеха загрузки ставок на сегодня. 

[Диаграмма контекста](c4_context.puml)

[Диаграмма контейнеров](c4_container.puml)

kafka заявлена в основном ADR по MVP - можно переиспользовать.

Принято решение использовать SFTP для колл-центра банка, чтобы не реализовывать ещё один тип интеграции. В случае
если колл-центру банка будет сильно удобнее принимать файл в ином формате - например HTTP или kafka, 
допустимо его рассмотреть и интегрироваться - это должно быть не сложно.

Загрузка файла через интерфейс - может быть оспорено, в случае, если системные аналитики команды предложат более удобный способ
загрузить файл в АБС. Если доработка на стороне команды АБС не предоставляется возможным - допустимо рассмотреть загрузку файла
напрямую в сервис открытия депозитов (HTTP, скрипт) любым администратором или СТП - это будет дешевле и удобнее.

### <a name="_bjrr7veeh80c"></a>**Альтернативы**

#### Загрузка файла СТП/администратором

Загрузка файла со ставками может производиться не через интерфейс АБС, а вручную ежедневно дежурной сменой СТП.
Тогда доработки в АБС можно не выполнять. Так же это сократит одну интеграцию на данном этапе.

#### Интеграция с кол-центром банка не по SFTP

Сейчас выбрана стратегии по SFTP с заделом на то, что CRM поддерживает такой подход и отображение файла в интерфейсе из коробке.
Допустимо перейти на любой альтернативный тип интеграции: email, http, kafka (приортет, так как по данном протоколу) - в случае если это существенно сократит объем работы.

### Недостатки, ограничения, риски

Недостатки:
* придётся либо доработать АБС, либо привлечь человеческие ресурсы и организовать процесс по загрузке ставок - процесс не сложный, но ввиду обеспечения гарантии доставки он будет вовлекать несколько разных отделов, а ещё и партнерский колл-центр;
* альтернативный способ интеграции с кол-центром -> SFTP с условием, что в рамках mvp разрабатывается интеграция по kafka


Риски:
* SFTP может работать не стабильно - требуется поддержать повторные обработки
* процессы по привлечению сотрудников для выполнения ручных операций в системе может быть не просто согласовать с соответствующими отделами.
